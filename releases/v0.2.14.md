# N-Lite v0.2.14

Fix the repeated cleaner permission prompts caused by rejecting the task permissions Windows actually returns.

- Keep the SYSTEM task registered after setup. Validate effective permissions while accepting Windows-normalized DACL flags and its redundant SYSTEM read entry. Standard users can read/run the task, but cannot edit its action or protected helper.
- Start the task directly through the Windows Scheduler API, avoiding stalled `schtasks.exe` subprocesses.
- Reuse the installed task for manual cleaning, automatic toggles and subsequent app sessions without invoking elevation.
- Persist unsuccessful setup attempts before launching the helper and verify both its exit result and the usable task before marking setup complete.
- Correct x64 standby memory counters to native pointer width. Both the app and helper now sum the real eight standby priority lists.
- Upgrade an existing protected helper once during installation. Windows asks for one repair/upgrade consent; routine app use does not reinstall it.

Verification includes Windows restricted-token integration tests for task installation, repeated toggles, automatic purge, a measured manual standby reduction, fresh process sessions, missing version markers, and the minute scheduler trigger with app sessions closed. Core regression and Windows startup enable/disable/delete tests also run before release.

A full Windows reboot and behavior on individual PCs are not reproduced by CI.

Download N-Lite-Setup-x64.exe to update. The portable package needs N-Lite.exe and N-Lite-Cleaner.exe together.
